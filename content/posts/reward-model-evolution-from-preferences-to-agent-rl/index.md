给模型一道题：解方程 `2x + 3 = 11`。

它可能生成三种回答：

```text
A：两边减3，得到2x=8；两边除以2，得到x=4。
B：两边减3，得到2x=9；所以答案是x=4。
C：先解释一大段方程知识，反复重述题目，最后正确得到x=4。
```

三份回答的最终答案都是 4，但需要评价的事情并不相同：

- A 与 B 的差别，是推理过程是否成立。
- A 与 C 的差别，可能涉及有效性、简洁性和用户偏好。
- 如果这只是长任务的一个中间步骤，还需要判断它有没有提高后续成功的机会。

奖励模型、过程奖励和信用分配，就是围绕这些差别展开的。

读这条路线时，最容易混淆的是：把所有分数都叫“奖励”，把所有评分器都叫“PRM”，再把所有训练循环都概括成“actor-critic”。这些概括有共同机制，却不足以解释每篇工作的实际改动。

这篇文章沿着问题演化整理我们读过的主线：**监督从哪里来，评分目标是什么，分数怎样进入策略更新，证据能说明什么。**内容来自论文与公开代码阅读；文中的数值例子除明确注明论文结果外，均为教学示例，不是本地训练成绩。

## 2. 起点：学习整篇回答的偏好，再用它优化生成模型

先看最直接的信号：同一道题，人更喜欢回答 A，而不是回答 B。

```text
输入数据：
问题 x
chosen 回答 y+
rejected 回答 y-

奖励模型输出：
rφ(x,y+) 和 rφ(x,y-)，各是一个标量。
```

经典 Bradley–Terry（BT）建模把偏好概率写成：

```text
P(y+ 优于 y-) = sigmoid(rφ(x,y+) - rφ(x,y-))

loss_RM = -log sigmoid(rφ(x,y+) - rφ(x,y-))
```

例如，两个奖励分别为 2 和 0，模型给 chosen 更受偏好的概率约为 0.881。训练推动排序正确，不要求标注者事先规定“好回答必须得 2 分”。

常见实现是在预训练 Transformer 上增加一个标量评分头。输入问题和完整回答，取回答末尾有效位置的表示，再投影成一个实数。该分数通常不是概率，也不必限制在 0 到 1。

[InstructGPT](https://arxiv.org/abs/2203.02155) 的经典流程是：SFT 建立起始策略，偏好排序训练 RM，再用 RM 提供奖励、通过 PPO 改进策略。

这里存在两个不同的学习阶段：

```text
训练 RM：
已有偏好对 → 两个分数 → BT loss → 更新评分器 φ

训练策略：
策略生成回答 → RM 打分 → 回报与优势 → 策略 loss → 更新策略 θ
```

RM 不是 Actor。PPO 中的 Critic 也不等于 RM：

| 角色 | 评价或输出什么 | 经典偏好 PPO-RLHF 中的常见更新方式 |
|---|---|---|
| Actor | 下一个 token 的生成分布 | RL 更新 |
| Reward Model | 完整回答的偏好质量 | 先训练，RL 阶段通常冻结 |
| Critic | 从当前前缀继续的预期回报 | 随策略训练 |
| Reference | 参考 token 概率，用于 KL 约束等 | 通常固定 |

这是典型配置，不是 PPO 的硬限制。PPO 可以接规则奖励、过程奖励，也可以配合在线评分器。数学答案验证和代码测试甚至可以直接提供结果奖励，不必先训练一个神经奖励模型。

最初的问题因此变成：**这个学习到的标量，能否可靠地代表我们希望优化的质量？**

## 3. 第一条支线：把“好回答”这个目标定义得更清楚

### HelpSteer2-Preference：评分与偏好，提供的监督不同

对同一组回答，可以收集两种标签：

```text
绝对评分：回答的帮助性是4分，正确性是3分。
相对偏好：回答A比回答B更好，而且好得比较明显。
```

前者可以训练回归模型，后者可以训练 BT 模型。[HelpSteer2-Preference](https://arxiv.org/abs/2410.01257) 的重要工作，是在匹配的数据上研究两种监督，并探索组合方法。

其中一条路径是先用帮助性评分训练模型，再初始化偏好模型。它还比较偏好幅度如何进入 loss：

```text
普通 BT：
-log sigmoid(r_chosen - r_rejected)

Margin BT：
-log sigmoid(r_chosen - r_rejected - m)

Scaled BT：
-m × log sigmoid(r_chosen - r_rejected)
```

后两者对偏好幅度的使用方式不同：一个要求分数差越过 margin，一个提高该样本的学习权重。论文中的 Pairwise Justifier 则输入两个回答，生成比较解释与结论；它和能独立评价单份回答的标量 RM，是不同接口。

### ArmoRM：先预测多个目标，再学习怎样组合

同一个回答可能准确但啰嗦，也可能流畅但不安全。单个偏好分数把这些差异压在一起。

[ArmoRM](https://arxiv.org/abs/2406.12845) 先学习多目标评分，再用依赖 prompt 的门控网络组合：

```text
多目标预测：[帮助性、正确性、连贯性、冗长程度……]
prompt → gating network → 各目标的组合权重
综合分数 = 多目标分数的加权组合
```

公开代码的路径是：在预计算特征上拟合多目标回归，再训练 prompt-conditioned gate。门控权重会随问题改变；推理时网络参数本身不因此发生学习。同一 prompt 下的一对回答，共享这套 prompt 条件权重。

这是对“如何表达偏好”的改进，但加权分数并不自动保证预算、事实、安全等硬条件全部满足。

### GRM：给奖励训练增加生成正则，改善泛化

训练集上的偏好顺序学得很好，换一批回答却失准，是另一个问题。

[GRM](https://arxiv.org/abs/2406.10216) 保留共享骨干的奖励头与语言模型头，用文本生成相关目标约束表示。用其 SFT 正则思路，可以概念化为：

```text
总loss = 偏好排序loss + λ × 文本生成正则loss
```

它改变的是 RM 的训练目标与泛化约束，不是 PPO 策略更新公式。GRM 也不同于名字相近的 GRAM；后者不属于这轮已经展开的主线。

这三项工作分别讨论标签形式、多目标表达和训练正则。接下来，评价单位也开始变化。

## 4. 从整篇结果，走向人工步骤监督

回到开头的 B：

```text
两边减3，得到2x=9。
所以答案是x=4。
```

最终答案检查会认为它答对，但逐步检查会发现错误。[Let’s Verify Step by Step](https://arxiv.org/abs/2305.20050) 研究过程监督，PRM800K 则提供约 80 万个步骤标签，而不是 80 万道题。

按照论文附录 D 的标注规则：

| 标签 | 简化含义 |
|---|---|
| +1 | 步骤合理、正确、易核验，并推进解题 |
| 0 | 合理、正确，但没有推进解题 |
| -1 | 不满足要求，例如计算错误或推理不合理 |

“Unsure”是标注处理状态，不是第四个预测类别。第二阶段发现首个负标签后，就结束该条解答的标注；后面未标注的步骤不能自行当成负例。

训练模型根据“题目＋截至当前的前缀”预测步骤标签。评分时再把步骤分数组合成整篇分数。原论文默认将 neutral 视为可接受，取各步骤可接受概率的乘积，并通过 Best-of-N 选择完整解答；其重点是奖励模型训练与候选选择，没有用 RL 更新生成器。

我们读过的 RLHFlow `math-rm` 是另一套实现：它用自动标签训练模型预测 `+/-`，评分脚本只取这两个 token 的 logits，做两项 softmax，并平均步骤分数。它不是 PRM800K 三类标签的原样实现。

这里还要分清实现细节：

```text
实际评分：
聊天格式 → token编号 → 标签预测位置的logits
        → P(+) → 步骤分数 → 汇总排序
```

预填的 `+` 用于构造评分格式，读取的是预测该标签的位置。脚本的 `-3` 索引依赖具体 tokenizer 与模板，不是所有 PRM 的通用位置。

过程监督让反馈更细，却带来了新的成本：**每一步的标签由谁来提供？**

## 5. Math-Shepherd：用后续结果，自动构造过程标签

[Math-Shepherd](https://arxiv.org/abs/2312.08935) 利用数学标准答案，从某个推理前缀反复继续解题，再检查各次最终结果。

```text
固定题目＋截至当前的前缀
              ↓
多次续写到最终答案
              ↓
比较标准答案
              ↓
构造当前步骤的监督目标
```

假设续写 8 次，5 次答对：

```text
硬标签 HE：
至少一次答对 → 1，否则 → 0。
本例标签为1。

软标签 SE：
正确次数 / 总次数。
本例标签为5/8 = 0.625。
```

再用这些目标监督训练 PRM。论文主要数据设置采用 8 次续写；之前读到的 RLHFlow 配置采用 16 次，要与原论文区分。

这条路线把部分人工成本转成了采样算力。训练好的评分器可以直接预测，不需要每次评分都重新采样。

它同时验证了两种用途：推理时排序候选，以及训练时在各推理步骤末尾给 PPO 提供反馈。原论文排序使用最低步骤分，和 PRM800K 的默认乘积、本地脚本的平均值都不同。

但这里已经发生了目标变化：标签直接测量的是“从这个前缀继续，有没有机会成功”，不再是人工对当前步骤的直接判断。

## 6. PRM Lessons：先问标签学到了什么，再问成绩代表什么

假设当前前缀写错了：

```text
2x=9。
```

续写模型发现错误，纠正成 `2x=8`，最后答对。MC 硬标签可能为正，但原来这一步确实错误。

反过来，正确前缀也可能因为后续模型能力不足而全部续写失败。

[PRM Lessons](https://arxiv.org/abs/2501.07301) 将这个混淆拆开：**当前步骤正确性和未来成功潜力，是不同的预测目标。**

它还检查了另一个问题：Best-of-N 只看选出的最终答案，会放过答案正确但过程有错的解答。在其初步对照实验中：

| 同一7B模型底座的训练数据 | Best-of-8 平均准确率 | ProcessBench 平均F1 |
|---|---:|---:|
| 人工 PRM800K | 64.9% | 56.5 |
| MC 硬标签 | 65.5% | 40.2 |
| MC 软标签 | 64.4% | 40.2 |

候选选择略好，不代表更会定位错误。这里是论文结果，不是我们本地复现。

论文提出把 MC 与强模型 Judge 结合，对错误位置判断一致的样本进行保留。共识过滤不是取两个分数的平均，也不能保证两者不会一起错；它用额外评判成本提高训练数据的一致性。

因此，评价 PRM 至少要分开回答：

1. 能不能选到正确答案？
2. 能不能检查过程错误？
3. 用来优化生成模型后，真实质量能否提高？

未来价值仍然可以有用，但需要按它真正的含义设计用法。

## 7. Rewarding Progress：奖励当前步骤带来的增量

假设同一搜索树里的两条不同分支有如下变化：

| 分支 | 当前步骤前的成功机会 | 当前步骤后 | 增量 |
|---|---:|---:|---:|
| A | 0.80 | 0.75 | -0.05 |
| B | 0.20 | 0.50 | +0.30 |

只看绝对价值，A 仍然更有希望；评价动作贡献，B 则带来了更多改善。

[Rewarding Progress](https://arxiv.org/abs/2410.08146) 研究如何利用这种进展。其步骤优势为：

```text
Aμ(s,a) = Qμ(s,a) - Vμ(s)

Qμ：固定采取a以后，由prover μ继续执行的预期结果。
Vμ：尚未固定a，由μ自己继续执行的预期结果。
```

估计 Q 时先固定候选步骤，再多次续写；估计 V 时，连下一步也由 μ 决定。成功比例来自结果检查，不是模型口头声称的 confidence。

论文进一步把基础策略的价值与 prover 的进展结合：

```text
有效评分／梯度权重 = Qπ(s,a) + α × Aμ(s,a)
```

同一前缀下，减去相同的 V 不会改变动作排序；进展还涉及跨前缀搜索和不同 prover 带来的监督。

prover 的重点是互补性。太弱的策略可能从所有分支都失败；在当前任务上过强的策略又可能把很多坏开头救回来，差异都不明显。

在其理想化推导中，如果 μ=π，额外加入自身 advantage 主要变成原有策略梯度的缩放，而没有引入新的评价信息。实际 PPO 有估计误差、裁剪等因素，不能把该推导理解为所有实现的训练轨迹完全相同。

这篇工作把焦点转向了奖励目标。但前缀采样成本和估值噪声仍然存在。

## 8. 隐式 PRM：只监督整篇，却得到可分解的奖励

[Free Process Rewards without Process Labels](https://arxiv.org/abs/2412.01981) 改变奖励参数化，减少对步骤标签的需求。

准备一个待训练的奖励语言模型 qφ，以及一个参考模型 qref。对已有完整回答 y，定义：

```text
整篇分数：
Rφ(x,y) = β × log[qφ(y|x) / qref(y|x)]

token奖励：
rφ,t = β × log[qφ(yt|x,y<t) / qref(yt|x,y<t)]

由于概率连乘、log将乘法变成加法：
Rφ = Σt rφ,t
```

它没有先推导每个 token 的真实对错，而是选择了一种天然可分解的整篇奖励表达式。

### 一组概率怎样产生过程奖励

将 `x=4` 简化为三个 token，令 β=1，忽略结束符等格式：

| token | qref条件概率 | qφ条件概率 | log概率比 |
|---|---:|---:|---:|
| x | 0.50 | 0.60 | 0.1823 |
| = | 0.80 | 0.80 | 0 |
| 4 | 0.20 | 0.60 | 1.0986 |

```text
R = 0.1823 + 0 + 1.0986 = 1.2809

qref(整篇) = 0.5 × 0.8 × 0.2 = 0.08
qφ(整篇)   = 0.6 × 0.8 × 0.6 = 0.288

log(0.288/0.08) = 1.2809
```

两个模型各自一次前向，就可以获得完整回答所有位置的条件分布。再取实际出现 token 的概率；因果遮罩保证每个预测位置看不到待预测 token 及后文。这里需要正确移位和回答 mask，不是把 token 自己读入后的输出误当成对它的预测。

### 只有整篇标签，loss怎样计算

用结果标签 z 训练一个 CE 实例：

```text
p = sigmoid(R)
loss_RM = -z×log(p) - (1-z)×log(1-p)
```

本例若 z=1，p≈0.7826，loss≈0.2451。对于 `x=5`，假设前两个概率相同，但 qφ 对 5 的概率为 0.1、qref 为 0.2，则 R≈-0.5108、p=0.375；负例 loss≈0.4700。

梯度通过总分传入语言模型。整篇为正，推动总分提高；整篇为负，推动总分降低。参考模型在此设置中固定。

### 分解出来的分数，为什么不是步骤正确概率

一个很罕见的 token，概率从 0.001 变成 0.01，就能得到正的 log(10) 分数。它反映相对参考的偏好，而不是绝对正确性。

单条样本只约束总和，也无法唯一确定局部分配：

```text
[1,1,0] 的总分是2。
[3,-1,0] 的总分也为2。
```

模型结构与其他样本会进一步约束分配，但没有直接提供逐步真值。

严格说，论文联系的前缀量是一种 soft value：

```text
F(前缀) = β × log E参考续写[exp(R(整篇)/β)]
token奖励 = F(新前缀) - F(旧前缀)
```

它不是简单的“真实答对次数／续写次数”。代数分解是精确的；学出的 R 是否可靠、局部分数是否有助于决策，则仍需要实验。

## 9. 有了过程分数，还需要决定怎样分配信用：PURE

假设 PRM 发出的奖励已经缩放为可正可负的数：

```text
奖励：[0.9, 0.9, -0.4, 0.9]
                    ↑
                 一个低分步骤
```

设 γ=1，普通后续累加回报是 `[2.3,1.4,0.5,0.9]`。第三步自己的奖励为负，未来正奖励却让它的回报仍为正。实际 advantage 还要扣基线，但这个例子显示了累加目标可能产生的抵消。

[PURE](https://arxiv.org/abs/2504.15275) 研究以整篇最低步骤分为目标，并提出 min-form 信用分配。严格形式中，唯一最差步骤之前及该步骤由最低分决定，最差步骤之后的过程回报为零：

| 位置 | 原始奖励 | 累加回报 | 严格min-form回报 |
|---|---:|---:|---:|
| 1 | 0.9 | 2.3 | -0.4 |
| 2 | 0.9 | 1.4 | -0.4 |
| 3 | -0.4 | 0.5 | -0.4 |
| 4 | 0.9 | 0.9 | 0 |

不能把严格实现简化成“所有位置都取自己的后缀最低分”，因为最差位置之后的处理不同。

论文通过奖励变换复用累加回报计算：

```text
wi = exp(-ri/T) / Σj exp(-rj/T)
r*i = wi × ri
```

有限温度是平滑近似；在唯一最小值、T趋近0、γ=1的条件下，奖励集中在最差步骤。转换后再计算回报、基线和优势，并可加入最终结果信号。

PURE 的主要实验使用 RLOO 思路，过程部分采用 token 级基线，并以最大生成长度归一化，研究不合适基线引起的步骤数偏置。

因此，它的改动位置是：

```text
PRM分数 → 奖励变换 → return → advantage → 策略loss
```

它没有把在线重训 PRM 作为核心算法。若评分器给无意义短句高分，最低分仍然可能很高；改变聚合方式无法修复评分盲点。论文也观察到纯 PRM 训练后期仍会被利用，加入少量可验证结果反馈有助于其设置下的稳定性。

## 10. 评分器也要跟着策略变化：PRIME

随着策略持续优化，它可能生成训练评分器时没有见过的新格式，或找到高分但质量差的写法。固定评分器可能逐渐失准。

[PRIME](https://arxiv.org/abs/2502.01456) 利用结果级标签训练隐式 PRM，使其能够持续使用当前策略的 rollout 更新：

```text
当前Actor生成多份回答
          ↓
答案验证／代码测试，产生结果标签
          ↓
隐式PRM用结果分类loss更新
          ↓
过程奖励＋结果奖励构造advantage
          ↓
策略loss更新Actor
          ↓
下一批新回答
```

关键是区分两个 loss：

| loss | 监督来源 | 更新谁 |
|---|---|---|
| 奖励模型CE | 生成回答的最终结果 | 隐式奖励模型 φ |
| 策略loss | 结果与过程奖励形成的优势 | 解题模型 θ |

Actor更新时，奖励和优势作为固定反馈，不能通过该策略 loss 随意改变评分器。

### 它和PPO的关系

PPO-RLHF 原本就可以有 Actor、RM、Critic、Reference。PRIME 的贡献不在于出现了两个模型，而在于结果监督下的隐式奖励在线更新，以及密集奖励的利用方式。

其主要方案用 RLOO 估计优势，并采用 PPO 风格裁剪目标。RLOO 是优势估计选择，裁剪是策略更新目标；不能因为有裁剪就把它与需要 Critic＋GAE 的标准 PPO 配置完全等同，也不能将它误写成默认 GRPO。

过程和结果信号分别处理，再合并优势。实现时的分组、token均值基线、折扣和mask都属于算法的一部分，不能只把过程总分随手加在原奖励上。

### 单前向与双前向

```text
单前向：
旧PRM前向并缓存奖励 → 更新PRM
→ 本轮Actor仍用缓存奖励；下一轮使用新PRM。

双前向：
旧PRM前向计算训练loss → 更新PRM
→ 新PRM再评同一批回答 → Actor使用新奖励。
```

单前向也会在线更新评分器。“双”不是指奖励模型与参考模型各运行一次，而是奖励模型更新前后多算一次。固定参考概率可以复用缓存。

论文默认采用单前向，观察到双前向提高了样本评分准确率，但训练结果奖励较接近。这并不支持“重算一定更好”。

原文核心 RL 场景是数学和代码：题目供Actor生成，标准答案或测试用例供验证，生成回答及其结果标签同时用于RM学习和策略改进。它没有因此证明在开放式写作或旅行规划上直接有效。

## 11. 走进Agent环境：MCTS、价值标签与AgentRM

把数学步骤换成环境动作：

```text
任务：把苹果放进冰箱。
状态：手里拿着苹果，冰箱门关着。
候选：打开冰箱／放到桌上／继续观察。
```

评价对象包含任务、历史动作和观察，不是动作名称的固定好坏。

[AgentRM](https://arxiv.org/abs/2502.18407) 的显式方案用 MCTS 式探索构造价值标签，再训练价值评估器，指导 Best-of-N 或逐步 Beam Search。

MCTS 的四个环节是：

```text
选择：平均价值与探索奖励，决定沿哪条分支继续。
扩展：提出新动作，产生子节点。
模拟：继续执行，取得环境结果。
回传：更新路径上的访问次数和价值统计。
```

它把搜索集中到有潜力或尚不充分探索的区域，不穷举所有路径。统计回传也不是神经网络反向传播；收集到状态价值后，才用MSE训练评分器。

这里需要保留一个实现边界：论文默认RM输入含历史信息与候选动作，但排除最后一个候选动作对应的新观察；加入该观察是单独的消融。因此，不能说每次评分都必须先执行候选动作。制造搜索数据和推进环境交互仍需要真实环境反馈。

AgentRM 与 MC 价值型数学 PRM 的机制相近。论文更关注：训练共享评分器来指导搜索，是否比直接微调策略更易跨任务迁移；也比较显式、隐式与Judge三条路线。

其论文表1中，同一8B策略的综合得分为：

| 方法 | 综合得分 |
|---|---:|
| Greedy | 52.7 |
| Best-of-5＋显式RM | 61.5 |
| Best-of-5＋隐式RM | 54.7 |
| Best-of-5＋Judge | 52.1 |
| Beam Search＋显式RM | 63.3 |

综合分包含成功率或进度指标的加权，不是统一成功率。与Greedy相比的8.8点含额外采样成本；Best-of-5各方案更接近匹配候选数量，但仍不能自动声称完全匹配计算成本。部分任务也会退化。

这条路线把昂贵探索经验压缩成可复用价值模型，成本没有消失：

```text
制造标签的生成与环境交互
＋价值模型训练
＋推理时额外候选和评分
```

它尤其依赖可重复或可恢复的环境，以及可信的任务结果。若业务环境难以分支、结果又难判断，MCTS不会自动解决这些前提。

## 12. 从挑好方案，进一步训练策略：AgentPRM

[AgentPRM](https://arxiv.org/abs/2502.10325) 同样使用未来价值，但主要将它放入策略迭代：

```text
π₀交互 → 聚合后续回报 → 训练Q₀ → 策略优化得到π₁
π₁交互 → 重新构造标签 → 训练Q₁ → 策略优化得到π₂
```

其主线可以理解为：

1. 并行、异步收集完整轨迹，计算每个状态—动作的后续回报，重复访问时聚合平均。
2. 用这些软目标训练Q(s,a)，论文主要用soft BCE。
3. 固定该轮Q，改进策略，再收集更新后的交互数据。

它避免必须为每个节点组织一棵同步搜索树，但没有消除采样成本与结果监督需求。长历史导致重复状态少，标签也可能很噪。

在“拿着苹果、冰箱关闭”的状态下，假设Q给“打开冰箱”0.8、“放到桌上”0.3。AgentRM可以据此选择候选；AgentPRM还会用Q排序策略生成的动作，通过Online DPO改变生成习惯。

其局部策略改进目标为：

```text
最大化 E[Q_i(s,a)]
− β × KL(新策略 || 上一轮策略)
```

参考上一轮策略，是因为Q来自上一轮的行为分布。更新过大可能离开估值可靠的区域。

论文允许PPO、Online DPO等优化工具，实际实验与本地主要脚本采用Online DPO。它不是新的PPO clipping，也不是首次提出actor-critic。贡献主要是将多轮环境价值学习，接成现成单轮RLHF工具能够利用的训练接口，并研究迭代、探索、塑形与过优化。

两篇Agent工作的重点可以这样比较：

| 维度 | AgentRM显式主线 | AgentPRM主线 |
|---|---|---|
| 标签构造 | MCTS式搜索统计 | 并行rollout的后续回报 |
| 价值训练 | MSE回归 | soft BCE |
| 核心用途 | 推理时搜索 | 价值与策略交替改进 |
| 策略参数 | 使用搜索时通常固定 | 每轮优化 |
| 研究重心 | 跨任务、跨策略泛化 | 交互学习与策略改进 |

AgentPRM也能在推理时使用候选动作Best-of-N。其ALFWorld实验中，3B策略直接执行的成功率从64.9%经三轮提高到88.1%，配合每轮Best-of-16达到91.0%。额外候选选择与策略本身的提升应分开看；这些成绩不能直接与AgentRM的综合分数横比。

## 13. 贯穿整条路线的评估：分数提高以后，任务是否真的更好

读完这些方法，最重要的评估问题没有改变：优化代理分数，是否改善真实目标？

### 分开检验目标、采样与预测误差

可以固定一批测试任务、前缀和候选，做四组诊断：

| 组别 | 过程信号 | 用途 |
|---|---|---|
| 基线 | 不加过程信号 | 建立原有水平 |
| 高精度参考 | 较多独立续写估计 | 检查该信号在此设置下是否有潜力 |
| 低采样估计 | 实际预算下的少量续写 | 检查采样误差 |
| 学习到的评分器 | 模型直接预测 | 检查拟合与泛化误差 |

高预算参考仍有误差，不是现实任务中的真值。对差异小、区间重叠的候选，不宜强行统计排序对错。

除了数值误差，还需要看符号错误、排序错误与选择损失。例如候选中最佳参考Qπ为0.60，而模型选中的候选仅0.35，这次选择损失就是0.25。对prover μ估得很准，也不代表其偏好一定适合π利用。

最终还要分别测搜索与训练：固定候选只能诊断选择，不能单独证明RL后策略会变好。

### 成本、分布与独立目标都要对齐

- 同样rollout数量下更好，说明可能更省样本；同样总算力下更好，才能支持整体计算更划算。
- 标签生成、环境交互、评分器训练与推理都要计入，必要时报告复用后的摊销成本。
- 新任务、新策略输出和新环境上的成绩，比刚训练过的数据拟合更重要。
- 同一任务的多个步骤相关，统计区间应按任务分组，避免把它们当成完全独立样本。
- 若声称步骤验证，就补错误定位评测；若目标是未来价值，就主要检验价值与下游决策，不把它硬解释为正确性检测。

这些是可采用的评估设计，不代表本地已经完成了这些实验。公开框架提供某个recipe，也不能作为工业界普遍采用的证据。

| 2025-02-03 | [PRIME](https://arxiv.org/abs/2502.01456) | 在线隐式RM＋密集奖励策略优化 | 在线更新不能自动修复验证器盲点 |
| 2025-02-14 | [AgentPRM](https://arxiv.org/abs/2502.10325) | 轮级价值学习与策略迭代 | 沿用经典actor-critic／策略迭代思想 |
| 2025-02-25 | [AgentRM](https://arxiv.org/abs/2502.18407) | 共享价值评分器指导Agent搜索 | 搜索收益包含额外候选与交互成本 |

这轮阅读还没有进入完整训练复现。可以沿本地公开代码继续核对三条链：

- BT：`bradley-terry-rm/gemma_2B_rm.py` 中，偏好对怎样成为两个标量和排序loss。
- PRM评分：`math-rm/prm_evaluate.py` 中，模板位置、标签token与分数聚合怎样对应。
- AgentPRM：`compute_prm_target.py → rm.py → online_dpo_vllm_thread.py` 中，交互轨迹怎样成为Q目标、评分器，再进入策略更新。折扣、状态去重、mask与参考策略需要按实际实现核对。

前两项位于[RLHFlow公开仓库](https://github.com/RLHFlow/RLHF-Reward-Modeling)，AgentPRM位于[作者仓库](https://github.com/sanjibanc/agent_prm)。代码阅读入口不代表环境已配置或训练已经跑通。

后续读到一个新名字，可以先填完这张记录卡，再评价它的创新：

```text
任务与决策粒度：
监督信号及来源：
分数的预测目标：
评分器loss：
reward → return → advantage 的构造：
策略更新loss：
实际更新哪些模型：
独立评测及匹配成本：
仍未解决的误差与泛化问题：
```

如果一篇工作只改变了标签来源，就按数据贡献评价；如果改变了回报与优势，就检查优化目标；如果沿用经典价值学习，则看它在新场景中的接口、实验与适用边界。这样才能看清这些方法各自推进了哪一步。
